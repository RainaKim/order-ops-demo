# labs/ 작성 규칙

## 이 폴더의 정의

`labs/`는 공식 course material이며 읽기 전용입니다. 실습 결과물은 `docs/`, `notes/`, `.github/`, `src/`, `tests/`에 둡니다.

## 절대 금지

- 정답, 예시 답안, 모범 문장, 그대로 붙여 넣으면 끝나는 완성 프롬프트를 넣지 않습니다.
- `solution/`, `.expected/`, `answer/` 폴더를 만들지 않습니다.
- `mkdir`, `touch`를 차례로 실행하게 하는 나열식 지시를 쓰지 않습니다.
- 검증 항목에 `예시:`로 시작하는 문장을 쓰지 않습니다.
- 확정된 산출물 파일명과 경로를 바꾸지 않습니다.
- 커리큘럼에 등재된 필수 산출물과 보조 산출물의 등급을 임의로 바꾸지 않습니다.
- 공개하지 않는 완성 산출물을 `labs/`에 복제하거나 링크하지 않습니다.

## README 표준 골격

lab별 README는 다음 7개 H2를 순서대로 사용합니다.

1. `## 0. 이 랩이 끝나면`
2. `## 1. 시작 전 상태 확인`
3. `## 2. 실습 목표와 산출물`
4. `## 3. 실습`
5. `## 4. Self-check`
6. `## 5. 자주 하는 실수`
7. `## 6. 다음 lab으로 넘기는 것`

`## 2. 실습 목표와 산출물`은 E 번호, 핵심 작업, 결과를 한눈에 확인할 수 있는 표로 작성합니다. 각 실습은 `설계 질문`, `실행`, `검증` 세 단계를 모두 포함합니다.

## 정량 규칙

- README는 원칙적으로 250줄 이내로 작성합니다. 강의자료 역할 때문에 길이 제한보다 완결성을 우선하는 Lab은 해당 rule의 `allowLongReadme`가 `true`일 때 예외로 둡니다.
- 실습 하나당 설계 질문은 2~4개, 검증 체크박스는 3~6개입니다.
- 자주 하는 실수은 4항목 이내이며 실제 수행 중 발생할 수 있는 것만 남깁니다.
- 프롬프트 뼈대는 빈칸(`______`)을 포함해 6줄 이내로 작성합니다.
- 긴 입력 자료는 `fixtures/` 또는 해당 lab의 `inputs/`로 분리합니다.
- 톤은 명확한 존댓말을 사용하고 이모지는 쓰지 않습니다.
- 독자를 특정 역할명으로 지칭하지 않습니다.
- 영상 단위 ID, 재생 시간, 촬영 순서, 발표자용 진행 큐를 넣지 않습니다.

## 검증 원칙

- 검증 문장은 참 또는 거짓으로 판정할 수 있어야 합니다.
- 필수 산출물은 누락 시 실패하고, 보조 산출물은 경고만 냅니다.
- `docs/`는 오래 사는 기준, `notes/`는 이번 작업 기록, `.github/`는 플랫폼 설정입니다.
- `labs/`는 실습 진행 중 읽기 전용으로 유지합니다.
