# Lab 18 실행 기록

## E1 Issue 합격 판정

**판정: 조건부 합격.** VOC는 불일치 조사와 Issue 초안 작성의 출발점이지만, 그 자체를 작업 Issue로 삼아 후속 저장소 탐색을 시작하기에는 범위와 완료 기준이 부족하다. 아래 확인 필요 사항과 사람 결정을 초안에 분리해 기록하고 사람이 검토한 Issue를 요청 원문으로 확정한 뒤 탐색한다. 구현 승인이나 원인 확정의 뜻은 아니다.

### 보고 사실

- [VOC](../labs/fixtures/l18-voc-report.md)에 따르면 고객은 첫 결제 실패 후 같은 주문을 다시 결제했고, 두 번째 요청의 성공 응답과 주문 상세의 결제 완료 표시를 봤다고 보고했다. 관리자 목록에는 성공 직후에도 결제실패가 표시됐으며 주문을 다시 처리해야 하는지 문의했다.
- 첫 토큰이 `FAIL`로 시작했다는 추가 정보가 있다. 두 번째 응답과 저장 상태·결제 이력의 일치 여부는 미확인이다. 고객 및 실제 카드 정보는 제거됐다.

### 저장소에서 확인한 사실

- [주문 정책](../docs/order-policy.md)은 실패 주문과 이력 보존, `payment_failed` 동일 주문 재결제 금지, 관리자 목록의 저장된 현재 상태 표시를 정한다. 실패 이력 존재만으로 다른 상태를 실패로 덮어쓰지 않는다. [결제 정책](../docs/payment-policy.md)은 실패 시 402와 실패 정보·이력, 재결제 거부 시 상태와 이력 불변을 정하고, [재고 정책](../docs/inventory-policy.md)은 실패 및 재결제 거부 시 재고 미차감·미복원을 정한다.
- 현재 [결제 코드](../src/payments.ts)는 `pending` 주문만 결제 가능하게 하고 `FAIL`로 시작하는 토큰에 실패 이력을 남겨 `payment_failed`로 바꾼다. 그 상태의 후속 결제는 결제 가능성 검사에서 거부된다. 이는 이 코드의 정상 경로에 대한 정적 확인이며 VOC 사건의 실행 환경이나 실제 기록을 확인한 것은 아니다.
- 현재 [관리자 코드](../src/admin.ts)는 같은 주문에 실패 이력이 하나라도 있으면 저장 상태 대신 `결제실패`를 표시한다. 이는 정책과 다른 코드상 동작이지만, 고객 사례의 원인으로 확정할 증거는 없다. 주문과 이력은 [메모리 저장소](../src/store.ts)에 있다.
- [기존 테스트](../tests/orders.test.ts)는 실패 주문 보존과 동일 주문 재결제 거부 시 주문·이력·재고 불변을 확인한다. 관리자 저장 상태 표시 정책 테스트는 `it.fails`로 표시돼 있고, 별도의 테스트는 현재 실패 표시와 실패 상세를 기대한다. 테스트 실행이나 고객 사례 재현은 이번 판정에 포함하지 않았다. README의 일부 엔드포인트 설명은 현 코드와 다르므로 위 현재 동작은 코드와 테스트를 기준으로 했다.

### 템플릿 아홉 필드 판정

| 필드 | 판정 | 근거와 필요한 보완 |
| --- | --- | --- |
| Summary | 충분 | 결제 후 주문 상세와 관리자 표시의 불일치 확인 및 재처리 문의라는 목표가 있다. |
| Context | 확인 필요 | 보고 시점과 순서는 있으나 사건의 실행 환경·버전과 저장 기록은 없다. |
| Current Behavior | 확인 필요 | 고객 관찰은 기재할 수 있지만 실제 응답·주문 상태·이력과 동일 주문 여부의 독립 확인 및 재현 조건이 없다. 현재 코드의 정상 흐름과도 차이가 있다. |
| Expected Behavior | 사람 결정 | 관리자 현재 상태 표시와 실패 주문 재결제 금지는 기존 정책으로 확정돼 있다. 이 사건에서 어떤 운영 조치를 원하는지와 보고된 성공을 어떻게 다룰지는 확인이 필요하다. |
| Scope | 사람 결정 | 조사 대상의 경계와 이번 Issue에서 다룰 범위가 정해지지 않았다. |
| Out of Scope | 누락 | 제외할 흐름과 후속 작업 경계가 명시되지 않았다. |
| Acceptance Criteria | 누락 | 상태·응답·저장 결과·테스트 증거를 관찰 가능하게 판정할 기준이 없다. 정책과 확인된 범위에 맞춰 작성하고 미결 값은 확정하지 않아야 한다. |
| Human Decision Needed | 사람 결정 | 사건 처리와 작업 범위의 결정을 명시해야 한다. 이미 금지된 동일 주문 재결제 허용 여부를 미결 정책으로 다시 제시하지 않는다. |
| References | 충분 | VOC, 템플릿, 관련 정책·코드·테스트를 이 기록에서 참조할 수 있다. 사건 자체의 근거 자료는 추가 확인이 필요하다. |

### 확인 필요와 사람 결정

- 조사로 확인: 실제 두 요청이 같은 주문과 같은 실행 환경에서 처리됐는지, 각 응답과 그 시점의 주문 상태·결제 이력, 관리자 조회 결과 및 재현 가능한 조건. 식별 정보와 카드 정보는 노출하지 않는 방식으로 확인한다.
- 사람 결정: 확인된 사건에 대한 운영 처리 여부와 범위, 이번 Issue의 포함·제외 경계 및 검증 가능한 완료 기준을 검토한다. 증거가 정책과 충돌하거나 새 정책 판단이 필요하면 구현 전에 사람에게 확인한다. 여러 실패 이력 중 표시할 이력의 선택 기준은 주문 정책상 별도 사람 결정 사항이며, 이 VOC에 여러 실패가 있었다고 가정하지 않는다.
- 다음 단계: 위 미확인·미결 사항을 남긴 Issue 초안을 작성해 사람이 검토하도록 한다. 실제 주문 재처리 여부는 이 자료만으로 판단하지 않는다.

## E2 Issue 등록 기록

- 사람이 [Issue 초안](issue-draft-l18.md)의 민감정보·미정 표시와 대상 저장소를 확인한 뒤 실습 저장소 `RainaKim/order-ops-demo`에 [Issue #1](https://github.com/RainaKim/order-ops-demo/issues/1)을 등록했다.
- 조회 시 Issue는 `OPEN`이며, 본문의 아홉 영역은 조사 범위와 사람 결정 항목을 유지한다. Issue 등록은 앱 구현 승인이 아니다.

## E3 탐색·코멘트 게시 기록

- URL 기반 상세 탐색은 [탐색 기록](issue-findings-l18.md)에 남기고, VOC 원문 파일만 사용한 별도 읽기 결과와 요청의 검토 상태·추적성을 비교했다.
- 사람이 공개 문안과 대상 Issue를 승인한 뒤 [탐색 코멘트](https://github.com/RainaKim/order-ops-demo/issues/1#issuecomment-6233780746)를 게시했다. 공개 문안은 확인 사실·가설·미정을 구분하며 고객 식별 정보·결제 정보와 내부 오류를 포함하지 않는다.
- 코멘트 게시 뒤 Issue의 `updatedAt`은 `2026-10-17T12:17:12Z`로 바뀌었다. 이후 단계는 댓글 없음으로 기록된 이전 탐색 snapshot이 아니라 갱신된 Issue를 다시 읽는다.

- 적용: [issue-kickoff](../docs/prompts/issue-kickoff.md), [planner](../docs/prompts/planner.md), [구현 계획 템플릿](../docs/templates/implementation-plan.md). 정책·코드·테스트와 탐색 근거를 대조했다.

- **상태: 사람 결정 및 계획 승인 대기.** 사건 운영 처리, 변경·제외 범위, 상태·응답·저장 결과와 검증 증거가 미결이다. 복수 실패 이력 선택 등 보류 정책은 해당 범위에 필요할 때 질문한다. 재결제 금지는 이미 확정된 정책이다. 사건 자료와 재현은 미확인이고 원인을 단정하지 않았다.

- 검증: `npm test` 24개 통과, `npm run lint`와 `npm run typecheck` 통과. `git diff --check` 통과 및 `src/`, `tests/`의 작업 트리 변경·미추적 파일 없음. `node labs/tools/check.mjs 18`은 권한 상승 재실행에서 Lab 18 산출물과 테스트·lint·typecheck를 통과했지만, 이전 Lab의 테스트 파일·문서 형식 누락으로 전체 실패했다. 최초 검사기 실행 시 테스트 포함을 미처 확인하지 못해 샌드박스에서 서버 바인딩 `EPERM`이 발생했으며, 위 권한 상승 테스트로 재확인했다. Lab 시작 커밋은 확인하지 않아 시작 커밋 대비 차이는 검증하지 않았다.
