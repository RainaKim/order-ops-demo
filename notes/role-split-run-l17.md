## 정책 근거 비교

`docs/order-policy.md`의 관리자 조회 기준은 다음을 요구한다.

- 저장된 주문을 목록 기준으로 삼고, `order.status === "payment_failed"`일 때만 실패 정보를 제공한다.
- 그 행의 상태는 `payment_failed`로 표시하며, 실패 시도 존재만으로 다른 저장 상태를 실패 상태로 덮어쓰지 않는다.
- 실패 금액·시각·사유는 같은 주문의 실패 이력에서 가져오며, 불일치에는 임의값을 쓰지 않는다.

`docs/payment-policy.md`는 실패 이력 보존, `payment_declined` 같은 안전한 정보만의 외부 제공, 실패 주문 보존을 뒷받침한다.

| 판정 | 역할 분리 | 단일세션 |
| --- | --- | --- |
| 안전한 사유 저장·노출 | 충족: 실패 이력과 응답에 `payment_declined`만 추가 | 충족: 동일 |
| 실패 정보의 조건부 제공 | 충족: 저장 상태가 `payment_failed`인 행에만 추가 | 충족: 추가 조건은 저장 상태를 사용 |
| 정책 상태 표시 | 충족: 행 상태가 저장된 `order.status` | 미충족: 실제 `payment_failed` 주문도 응답 상태가 `결제실패`가 됨 |
| 불일치 은폐 방지 | 부분 충족: 사유 누락은 500이나 비정상 금액·시각은 통과 가능 | 충족: 실패 이력의 사유·금액·시각을 확인하고 500 처리 |
| 최근 이력 선택 | 충족: 유효한 일반적 타임스탬프에서는 최근값 선택 | 충족: 완료된 이력 중 최근값 선택 |

따라서 정책 충족 범위는 역할 분리본이 상태 표시에서 우세하고, 단일세션본이 실패 이력 완전성 검증에서 우세하다. 두 구현 모두 정책의 모든 요구를 완전히 충족한다고 보기는 어렵다.

## 계획 근거와 이탈

역할 분리본의 계획은 아직 구현 시작 상태를 `미승인`으로 남기며, `deriveDisplayStatus()`의 본문·시그니처·삭제·리팩터링을 제외한다고 썼다. 단일세션본의 계획은 구현 승인을 기록하고 검증 결과도 적었으며, `deriveDisplayStatus()`의 본문과 호출 방식을 변경하지 않는다고 명시했다.

| 점검 항목 | 역할 분리 | 단일세션 |
| --- | --- | --- |
| 계획의 구현 승인 기록 | 이탈: 계획에는 미승인이라고 남아 있으나 `src/`·`tests/`가 변경됨 | 일치: 승인 및 구현 시작이 기록됨 |
| 계획의 상태 표시 경계 | 이탈 가능성: 호출 제거로 기존 표시 동작을 변경. 정책 목표에는 맞음 | 일치: 호출 방식과 기대 실패 테스트를 보존 |
| 계획의 불일치 이력 검증 | 이탈: 금액·시각 완전성 테스트가 없고 구현도 검증하지 않음 | 일치: 사유가 없는 이력의 500 테스트가 있음. 다만 잘못된 금액·시각은 직접 검증하지 않음 |
| 계획의 고아 이력 검증 | 충족: 고아 이력으로 행을 만들지 않는 테스트 추가 | 미흡: 계획에 적었으나 전용 테스트 없음 |
| 계획의 민감 정보 검증 | 충족: 저장 객체와 관리자 응답의 금지 값·필드를 검사 | 부분 충족: 관리자 응답의 카드 토큰·오류 메시지 비노출은 검사하지만 저장 객체의 금지 필드는 직접 검사하지 않음 |
| 계획 외 파일 | 이탈: `docs/prompts/planner.md`, `implementer.md`, `reviewer.md`가 계획 파일 목록 밖에 untracked로 존재 | 없음 |

역할 분리본은 정책 상태 요구를 해결하기 위해 단일세션 계획이 명시적으로 보존한 관찰 대상(`deriveDisplayStatus()` 호출과 `it.fails()`)을 변경했다. 반대로 단일세션본은 그 관찰 대상을 보존하기 위해 현 정책의 상태 표시 요구를 남겼다. 이 선택은 계획과 정책 중 무엇을 우선하는지에 대한 사람의 명시적 결정 없이는 하나로 합치면 안 된다.

## 검증 근거

현재 작업 트리에서 재실행한 결과다. Supertest 기반 테스트이므로 로컬 HTTP 바인딩 권한으로 실행했다.

| worktree | `npm test` | `npm run lint` | `npm run typecheck` | `git diff --check` |
| --- | --- | --- | --- | --- |
| 역할 분리 | 통과 — 15개 테스트 | 통과 | 통과 | 통과 |
| 단일세션 | 통과 — 15개 테스트 | 통과 | 통과 | 통과 |

단일세션의 테스트는 불완전 실패 이력 케이스에서 `console.error`로 내부 오류 문맥과 스택을 stderr에 기록했다. HTTP 응답 테스트는 통과했고 응답에 그 정보가 포함되지 않음을 검사했지만, 테스트 출력에는 해당 내부 문맥이 보인다. 역할 분리본은 같은 케이스에서 `console.error`를 spy로 대체해 출력하지 않았다.

두 worktree 모두 기록된 기존 검증 결과와 현재 재검증 결과가 15개 테스트 통과로 일치한다. 다만 테스트 통과는 위 정책·계획 이탈을 해소하는 근거가 아니다.

## 결론과 후속 결정

- 정책 상태 표시를 우선하면 역할 분리본의 `order.status` 직접 사용을 기준으로 삼되, 이력 완전성 검증을 단일세션 수준으로 강화하고 계획 승인·범위를 정정해야 한다.

- 이 기록은 비교 결과만 담는다. 두 구현을 합치거나 다른 파일을 수정·커밋하지 않았다.

## 현재 diff 재확인 및 preflight 결과 — 2026-10-17

위 비교·검증 표는 당시 스냅샷이다. 이후 후속 수정이 있었으므로 현재 역할 분리 worktree의 상태를 나타내지 않는다.

- **당시 체크리스트 적용: 미실행.** `docs/checklists/pr-preflight.md`가 이 worktree에 없어서 당시에는 항목을 확인하지 못했다. 이후 사용자가 제공한 원래 checkout의 경로를 사용한 재적용 결과는 아래에 기록한다.
- 별도로 현재 diff를 확인했다. 추적 변경은 `src/admin.ts`, `src/payments.ts`, `src/store.ts`, `tests/orders.test.ts` 네 파일이며, 구현 계획의 기존 구현 파일 목록과 일치한다. 미추적 파일은 역할 프롬프트 세 개, 구현 계획과 이 기록이다. 프롬프트는 계획에서 앱 구현과 분리된 산출물로 명시했다. 이 목록은 체크리스트 적용을 대신하지 않는다.
- 현재 `deriveDisplayStatus()` 호출은 보존되어 실패 이력이 있으면 관리자 상태를 `결제실패`로 표시한다. `docs/order-policy.md`의 `payment_failed` 표시 요구와 불일치하며, 계획에 따라 다음 실습으로 인계한다. 정책 상태 테스트는 `it.fails()`로 실행되는 **기대 실패**다.
- 현재 diff는 실패 이력의 금액·시각·사유를 검증하고 불완전한 경우 500을 반환하는 코드와 테스트를 포함한다. 복수 이력의 동일 시각 선택 기준은 미결이며 동률 처리는 확인되지 않았다.
- `git diff --check`: 통과(종료 코드 0). 이 명령은 미추적 파일 내용을 검사하지 않는다.

| 검증 명령 | 이번 실행 결과 |
| --- | --- |
| `npm test` | 종료 코드 0, Vitest 보고 24개 통과. 이 중 관리자 정책 상태 검사는 `it.fails()`의 기대 실패이므로 일반 정책 검증 통과로 보지 않는다. Supertest의 로컬 HTTP 바인딩을 위해 권한 상승 실행. |
| `npm run lint` | 통과, 종료 코드 0 |
| `npm run typecheck` | 통과, 종료 코드 0 |

당시에는 이 기록만 수정했으며 stage·commit하지 않았다. 당시에는 체크리스트 부재와 상태 표시 정책 불일치가 남아 PR 준비 완료로 판정하지 않았다.

## 승인된 PR preflight 재적용 — 2026-10-17

사용자가 Lab 16의 승인된 입력으로 지정한 [`../order-ops-demo/docs/checklists/pr-preflight.md`](../../order-ops-demo/docs/checklists/pr-preflight.md)의 일곱 항목을 현재 작업 트리에 적용했다. 기준선 `20800f4b921442f75d557d67c6f2486c701c32d1`과 추적 diff 및 미추적 파일 목록·내용을 확인했다. staged diff는 비어 있으며, 아직 PR diff는 존재하지 않아 그 대상은 확인하지 못했다.

| 항목 | 판정 | 근거 및 필요한 후속 조치 |

## Preflight 사람 판정 — 2026-10-17

위 preflight 결과에 대해 사용자가 다음과 같이 결정했다. 이 판정은 위의 당시 판단 중 해당 항목의 후속 조치를 갱신한다.

1. 관리자 상태의 정책 불일치는 `it.fails()` **기대 실패**로 유지하고 다음 작업으로 인계한다. 정책 불일치가 해결되었거나 일반 테스트가 통과했다는 뜻은 아니다.
2. 복수 실패 이력의 동일 시각 선택 기준은 정책 미결로 보류한다.
3. `docs/prompts/planner.md`, `docs/prompts/implementer.md`, `docs/prompts/reviewer.md`는 공식 산출물로 이번 커밋에 포함한다. 위의 포함 여부 확인 필요 판정은 이 결정으로 해소됐다.
4. 위 항목들은 모두 이번 작업의 블로커가 아니다.

이 판정은 아직 확인하지 못한 다른 경계나 staged/PR diff 검토의 결과를 대신하지 않는다. 이 기록 단계에서는 다른 파일을 수정하거나 stage·commit하지 않았다.
