## Goal

`labs/lecture12/inputs/l12-issue.md`의 완료 기준을 다음 관찰 가능한 결과로 연결한다.

- 주문 품목의 동일 `productId` 수량을 먼저 합산한다. 한 품목이라도 합산 수량보다 재고가 부족하면 주문 전체를 거절하며, 주문은 저장되지 않고 충분했던 다른 품목을 포함해 어떤 재고도 변경하지 않는다.
- 모든 품목의 재고가 충분할 때만 `pending` 주문을 저장하며, 주문 생성만으로 재고를 차감하지 않는다.
- 재고가 충분한 `pending` 주문은 성공 결제 뒤에만 주문 수량만큼 한 번 재고가 감소하고 `paid`가 된다.
- 실패 결제 뒤 주문은 `payment_failed`로 남고, 해당 실패 결제 시도 기록도 보존된다.
- 관련 테스트와 `npm test`, `npm run lint`, `npm run typecheck`이 통과한다.

미결: 실패 사유의 필드·허용 값은 이 계획의 확정 결과로 넣지 않는다. 결제 시점 재고 부족은 HTTP 409, `pending` 유지, 재고·결제 이력 무변경으로 승인되었다. `payment_failed` 주문의 재결제는 전용 응답을 만들지 않고 기존 일반 거부 응답인 HTTP 400과 `{ "message": "Order is not payable" }`를 임시 계약으로 사용한다.

### Step 3 — 결제 결과와 재고 반영

- 입력 근거: 결제·재고·주문 상태 정책과 사람 결정
