## Summary

결제 실패 후 재결제에 성공했다는 고객 보고와 관리자 주문 목록의 표시가 다른 사례를 조사한다. 주문 재처리 필요 여부는 사건 확인 후 판단한다.

## Context

고객은 결제 실패 후 다시 결제했으며, 두 번째 결제 성공 직후 관리자 목록을 확인했다고 보고했다. 실행 환경과 버전, 실제 저장 기록은 미확인이다.

## Current Behavior

- **고객 보고:** 같은 주문의 두 번째 결제가 성공했고 주문 상세에 결제 완료가 표시됐지만, 관리자 목록에는 결제실패가 계속 표시됐다.
- **미확인:** 두 요청의 실제 주문·실행 환경, 각 응답, 당시 주문 상태와 결제 이력, 관리자 조회 결과 및 재현 조건. 두 번째 응답과 저장 결과의 일치 여부도 확인되지 않았다.
- **저장소 확인:** 현재 결제 코드는 실패 주문을 `payment_failed`로 보존하고 해당 상태의 재결제를 거부한다. 관리자 코드는 해당 주문에 실패 이력이 있으면 저장 상태 대신 결제실패를 표시한다. 이는 코드의 정적 관찰이며 보고된 사건의 원인이나 재현 결과는 미정이다.

## Expected Behavior

- 주문 정책에 따라 관리자 목록은 저장된 현재 주문 상태를 표시하며, 실패 이력만으로 다른 상태를 실패 상태로 덮어쓰지 않는다.
- 결제 실패 주문과 이력은 보존하며 `payment_failed` 주문의 동일 주문 재결제는 거부한다. 거부 시 주문 상태와 결제 이력은 바뀌지 않고 재고는 차감하거나 복원하지 않는다.
- 이 사건의 운영 처리와 작업 완료 범위는 미정이며 사람의 결정이 필요하다.

## Scope

- 우선 보고된 요청·응답과 주문 상태, 결제 이력, 관리자 표시의 관계를 확인하고 정책 및 현재 코드·테스트와 대조한다.
- 구체적인 변경 범위와 영향을 받는 흐름은 조사 결과를 바탕으로 사람이 확정한다.

## Out of Scope

- 실제 주문 재처리와 외부 결제 연동은 이 조사에서 수행하지 않는다.
- 그 밖의 제외 범위와 후속 작업은 미정이며 사람이 확정한다.

## Acceptance Criteria

- [ ] 고객 보고와 확인된 사실을 구분하고, 두 요청의 동일 주문 여부·응답·당시 저장 상태와 이력·관리자 조회 결과를 확인하거나 확인하지 못한 항목과 이유를 기록한다.
- [ ] 재현 조건과 실행 환경을 확인하거나 미확인으로 기록하고, 현재 코드와 보고의 차이를 사건의 원인으로 단정하지 않는다.
- [ ] 정책상 관리자 표시 기준과 실패 주문 재결제 거부 시 주문·결제 이력·재고의 기준을 확인한 근거와 함께 기록한다.
- [ ] 조사 결과에 따른 변경 범위, 상태·응답·저장 결과의 구체적인 완료 기준 및 이를 검증할 테스트는 사람이 결정한 뒤 기록한다. 응답의 미결 세부 값은 추측하지 않는다.

## Human Decision Needed

- 사건의 실제 상태와 이력이 확인되면 주문에 어떤 운영 처리가 필요한가?
- 이번 Issue에 포함할 변경 범위와 제외할 후속 작업은 무엇인가? 조사 결과를 반영한 관찰 가능한 완료 기준과 검증 증거를 승인해 주세요.
- 조사 중 정책 충돌이나 정책상 보류된 상황이 발견되면 어떻게 처리할지 결정해 주세요. 동일 주문의 `payment_failed` 재결제 금지는 이미 승인된 정책이다.
