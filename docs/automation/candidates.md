# 자동화 후보 판정

이 문서는 Lab 19 E1 판정과 E2의 최소 표면·권한 심사 결과다. 일반 세션의 시험은 Scheduled 권한의 증거가 아니며, 자동 실행이나 후보 승인을 뜻하지 않는다. 출력은 검토용이며 구현, GitHub 쓰기, 정책 확정을 포함하지 않는다. 여섯 필드의 미확인 항목은 실제 시험 전까지 유지한다.

## 새 Issue의 관련 파일 후보 정리

**판정: 조건부.** [Lab 08 Issue 진단](../../notes/issue-diagnosis-l08.md)은 Issue 입력에서 정책·코드·테스트 경로를 열거하고 정책과 현재 코드를 대조했다. [Lab 18 탐색](../../notes/issue-findings-l18.md)은 다른 Issue를 입력으로 읽은 경로, 파일 역할·현재 동작, 미확인 사항을 기록했다. 두 기록 모두 요청에서 관련 자료를 찾아 역할과 근거를 남겼다는 점에서 반복되지만, 전자는 샘플 Issue 진단, 후자는 실제 Issue 심화 탐색으로 출력 전체가 같지는 않다. [kickoff prompt](../prompts/issue-kickoff.md)는 재사용 절차이지 독립 실행 증거는 아니다.

| 기준 | 판단 |
| --- | --- |
| 반복 근거 | 두 Issue에서 관련 정책·코드·테스트를 찾아 근거로 연결한 공통 부분은 확인; 동일한 파일 후보 목록 형식의 반복은 미확인. |
| 입력 안정성 | Issue 원문·조회 시점과 저장소 경로는 가변 입력으로 분리 가능하나, 최신 댓글과 범위는 매회 확인 필요. |
| 실패 영향 | 읽기 전용 후보에 머물면 잘못된 파일 누락·범위 오인이 후속 계획을 오염할 수 있다. |
| 사람 판단 | 범위·정책·완료 기준과 후보의 채택은 사람이 결정한다. |
| 자동 실행 권한 | 로컬 자료 읽기는 필요; 원격 Issue는 GitHub 네트워크가 필요하다. 자동 실행 환경의 네트워크·인증 접근은 미확인. |

**표면·권한 및 직접 시험:** 로컬 입력이면 파일 읽기와 CLI 검색만으로 착수한다. 현재 일반 세션의 workspace-write sandbox에서 샘플 Issue, 코드·테스트·정책을 `rg`와 `sed`로 읽었다. 샘플을 통한 입력·검색 시험이지 새 원격 Issue의 최신성이나 전체 kickoff 수행을 증명하지 않는다. 이 시험에 웹·GUI는 사용하지 않았다. 실제 최신 Issue URL을 kickoff 원문으로 쓰려면 GitHub 네트워크와 인증된 읽기 접근이 필요하며, 해당 `gh issue view`는 이번에 실행하지 않아 접근 및 Scheduled 권한은 미확인이다. 사람 제공 스냅샷은 로컬 분석용이며 최신 Issue 검증을 대체하지 않는다. 최소 목표는 로컬 입력·보고만의 read-only이며 그 sandbox와 Scheduled 실행은 미시험이다.

- **Input:** Issue URL과 최신 본문·댓글·조회 시점, 관련 정책·코드·테스트. 로컬 사본을 사용하면 출처·시점과 최신성 미확인을 명시한다.
- **Output:** CLI/일반 세션에서 파일별 역할·근거·미확인을 보고한다. 별도 파일로 저장할 때만 workspace 쓰기가 필요하며 자동 실행에서의 쓰기 권한은 미확인이다.
- **Run Condition:** 대상과 입력이 제공되고 필요한 읽기가 가능할 때. URL 기반 kickoff는 네트워크·인증 접근을 확인한 때만 진행한다. Scheduled는 검증된 절차의 시간 실행 후보이며 시험·생성되지 않았다.
- **Stop Condition:** 원격 접근 실패·권한 필요, 오래되었거나 확인 불가한 입력, 정책 누락·충돌·보류 또는 민감정보 발견 시 해당 의존 작업을 중단하고 보고한다.
- **Human Approval Needed:** 범위·정책 결정과 후보 채택; 외부 게시나 구현은 별도 승인 필요. Scheduled의 적합성과 권한은 사람 검토가 필요하다.
- **Failure Alert:** 대상·입력 출처·조회 시점, 완료 단계, 미실행 명령·접근 실패·필요 권한 및 사람 결정 사항을 보고한다. 외부 알림·전달 수단은 미확인이다.

## 테스트 실패 로그 요약

**판정: 수동 유지.** [Lab 13 실패 기록](../../notes/error-log-l13.md)은 같은 주입 오류에 대한 typecheck와 테스트 변환 실패의 명령·종료 코드·오류 위치를 비교하고 복구 뒤 결과를 기록했다. 서로 다른 명령과 복구 전후는 한 사건의 비교이지 독립적인 반복 작업이 아니다. 다른 독립 실패 로그를 같은 입력 처리·판정·출력으로 요약한 기록은 확인하지 못했다. [Lab 18 실행 기록](../../notes/issue-run-l18.md)의 EPERM 언급은 간단한 검증 이력으로, 같은 요약 절차의 반복 증거가 아니다.

| 기준 | 판단 |
| --- | --- |
| 반복 근거 | 독립적인 반복 미확인; 확인된 통제 실패 사건은 하나. |
| 입력 안정성 | 명령·원본 로그·종료 코드·실행 시점은 분리 가능하나 로그 형식과 충분한 문맥은 매회 달라진다. |
| 실패 영향 | 잘못된 원인 추정이나 테스트 미수집을 통과로 오인하면 후속 수정·판정에 영향을 준다. |
| 사람 판단 | 원인·복구 범위와 불명확한 실패의 분류는 사람이 확인한다. |
| 자동 실행 권한 | 제공된 로그 읽기만 할 때의 자동 실행 접근은 미확인; 테스트 재실행에는 로컬 서버 바인딩 권한이 필요할 수 있으며 자동 실행 가능 여부는 미확인. |

**표면·권한 및 직접 시험:** 로컬 파일 읽기와 CLI 검색으로 충분한 자료를 제공받아 요약한다. 현재 workspace-write 일반 세션에서 `rg`로 Lab 13 기록의 종료 코드·변환 오류·`0 test`를 확인했다. 이는 이미 정리된 기록을 읽은 부분 시험이며 새로운 원본 로그의 재현·원인 확정이나 반복성을 증명하지 않는다. 웹·GUI·Scheduled는 사용하지 않았다. 최소 목표는 read-only와 보고이지만 해당 sandbox 및 Scheduled 권한은 미시험이다. 로그 요약 자체에 테스트 실행이나 서버 바인딩은 필요하지 않다.

- **Input:** 로컬 원본 로그, 대상 명령·종료 코드·실행 시점·수집 상태. 누락 값은 미확인으로 둔다.
- **Output:** 일반 세션 보고에 첫 오류·위치·실행/미실행·수집 여부와 불명확한 원인을 구분한다. 파일 저장 시 workspace 쓰기가 추가로 필요하다.
- **Run Condition:** 충분한 로그가 주어진 수동 검토만 수행한다. 독립 반복 근거 부족으로 Scheduled 후보 승격은 보류한다.
- **Stop Condition:** 로그 누락·민감정보·원인 불명 또는 추가 접근이 필요하면 추정하거나 자동 재실행하지 않고 보고한다.
- **Human Approval Needed:** 원인·복구 조치 및 별도 재실행 판단. 재실행이 필요하면 대상 명령과 서버 바인딩 등 권한을 별도 확인한다.
- **Failure Alert:** 대상 로그·명령·완료 단계, 누락 및 필요한 접근·사람 결정을 보고한다. 외부 알림 수단은 미확인이다.

## PR preflight 실행

**E3 선택:** 사람이 PR preflight를 Skill 대상으로 승인했고, [`pr-preflight`](../../.agents/skills/pr-preflight/SKILL.md)를 생성했다. 범위는 승인된 입력에 대한 체크리스트 근거와 보류 보고이며, 최종 PR 준비·정책·범위 결정은 사람이 맡는다. Skill 형식과 명령을 일반 세션에서 확인했지만 새 세션에서의 Skill 호출·일반 요청 비교와 Scheduled 권한은 미확인이므로 동작 검증은 조건부다. 실행별 증거는 [E3 기록](../../notes/automation-run-l19.md#e3-skill-시험)에 있다.

**판정: 조건부.** [Lab 16 실행 기록](../../notes/preflight-run-l16.md)과 [Lab 17 재적용 기록](../../notes/role-split-run-l17.md)은 서로 다른 변경에 같은 [일곱 항목 체크리스트](../checklists/pr-preflight.md)를 적용하고 항목별 근거·결과·판정을 남겼다. Lab 17은 체크리스트 부재를 먼저 미실행으로 기록하고 제공받은 뒤 재적용했으므로 반복 수행과 중단 경계의 근거다. 같은 절차가 반복되어도 두 결과 모두 정책 불일치 등을 별도로 보류했다.

| 기준 | 판단 |
| --- | --- |
| 반복 근거 | 독립 작업에서 Scope, Policy, Tests, Lint, Typecheck, Diff, Failure handling을 대조한 실행·판정이 반복됨. |
| 입력 안정성 | 기준선·diff·승인 계획·정책·검증 결과를 실행별 입력으로 분리 가능. |
| 실패 영향 | 읽기·검증 결과는 잘못된 PR 준비 판정으로 이어질 수 있다. stage·commit·게시까지 자동화하지 않는다. |
| 사람 판단 | 범위 승인, 정책 불일치·기대 실패의 수용 및 최종 PR 준비 판정은 사람이 맡는다. |
| 자동 실행 권한 | 테스트의 Supertest 로컬 서버 바인딩에 권한 상승이 필요한 기록이 있다([Lab 17](../../notes/role-split-run-l17.md)); 자동 실행 환경에서 실행 가능 여부는 미확인. 네트워크·외부 쓰기 없이 전체 입력을 얻을 수 있는지도 미확인. |

**표면·권한 및 직접 시험:** 로컬 파일과 CLI의 Git·검증 명령이 필요하다. 현재 일반 workspace-write sandbox에서 `git diff --name-status`, `git diff --check`, `git status --short`, `npm run lint`, `npm run typecheck`가 각각 종료 코드 0이었다. `npm test`는 지침에 따라 처음부터 로컬 서버 바인딩용 권한 상승으로 실행해 종료 코드 0, 24개 통과 집계였다. 이 중 관리자 정책 검사는 `it.fails` 기대 실패다. 좁은 sandbox에서 테스트는 실행하지 않았고, 권한 상승 성공은 Scheduled 가능성을 증명하지 않는다. 이 명령 시험은 대상 PR·승인 계획을 특정해 일곱 항목을 판정한 전체 preflight가 아니다. 원격 PR diff가 필요하면 네트워크·인증 읽기가 추가되며 미시험이다. 웹·GUI는 이 로컬 시험에 불필요하다. Scheduled는 검증·사람 승인 후에만 고려하며 해당 sandbox·명령 권한은 미확인이다.

- **Input:** 로컬 기준선·작업 트리·staged diff, 존재 시 PR diff, 승인 계획·정책·체크리스트·검증 명령. 원격 PR 입력은 별도 네트워크·인증 읽기 필요.
- **Output:** CLI/일반 세션 보고에 일곱 항목별 근거·명령 결과·통과/보류/미실행 및 사람 결정을 기록한다. 파일 저장 시 workspace 쓰기가 추가로 필요하다.
- **Run Condition:** 대상·기준선·승인 계획과 자료가 확인된 때 실행한다. 테스트는 필요한 로컬 서버 바인딩 권한이 있을 때만 실행하고, Scheduled 권한은 미확인으로 둔다.
- **Stop Condition:** 자료·권한 부재, 정책·범위 미결 또는 실패 시 해당 판정을 보류하고 마지막 완료 단계와 미실행을 보고한다. 자동으로 stage·commit·게시하지 않는다.
- **Human Approval Needed:** 변경 범위, 정책·기대 실패 처리, 최종 PR 준비 판단 및 Scheduled 사용 여부.
- **Failure Alert:** 대상·기준선, 완료 단계, 명령별 종료 상태·미실행 이유, 남은 변경·필요 권한·사람 결정을 보고한다. 외부 알림 수단은 미확인이다.

## 문서와 코드 불일치 후보 찾기

**판정: 조건부.** [Lab 14 assertion 검토](../../notes/assertion-review-l14.md)는 정책·현재 구현·테스트를 대조해 재고 부족 응답의 정책 보류와 관리자 표시 차이를 기록했다. [Lab 18 탐색](../../notes/issue-findings-l18.md)은 정책과 코드·테스트를 다시 대조하고 README의 과거 동작 설명도 지적했다. 두 기록에 기준과 현재 동작을 비교하고 차이·미결을 기록하는 공통 절차가 있다. 관리자 표시 차이는 같은 불일치의 재관찰이므로 독립 결함 수로 세지 않는다. 두 기록의 전체 출력 형식은 다르다.

| 기준 | 판단 |
| --- | --- |
| 반복 근거 | 서로 다른 검토에서 정책/문서·코드·테스트를 대조한 공통 절차는 반복; 완전히 동일한 출력 형식은 미확인. |
| 입력 안정성 | 비교할 문서·코드·테스트와 버전은 가변 입력으로 지정 가능; 규범과 과거 설명의 구분이 필요하다. |
| 실패 영향 | 잘못된 불일치 후보가 정책이나 현재 동작을 오인하게 할 수 있다. 후보 보고에만 한정한다. |
| 사람 판단 | 정책의 의미·우선순위·수정 여부와 범위는 사람이 결정한다. |
| 자동 실행 권한 | 로컬 파일 읽기로 정적 대조가 가능하나 자동 실행 환경의 접근은 미확인; 실행 재현이나 외부 자료가 필요할 때의 권한도 미확인. |

**표면·권한 및 직접 시험:** 로컬 문서·코드·테스트 읽기와 CLI 검색을 사용한다. 현재 workspace-write 일반 세션에서 `rg`와 `sed`로 README의 생성 시 차감·실패 주문 삭제 설명과 주문 생성·결제 코드의 현재 경로를 대조했다. 생성 경로는 재고 검사 뒤 차감 없이 주문을 저장하고, 실패 경로는 상태를 `payment_failed`로 바꾼다. 이는 정적 불일치 후보 두 개의 부분 시험이며 모든 경로의 실행 검증이 아니다. 웹·GUI는 사용하지 않았다. 최소 목표는 read-only와 보고이나 해당 sandbox 및 Scheduled 권한은 미시험이다.

- **Input:** 로컬 문서·코드·테스트 경로와 기준 버전·비교 범위. 자료의 규범과 과거 설명을 구분한다.
- **Output:** 일반 세션 보고에 주장 유형·코드 관찰·근거 경로·차이와 미확인을 기록한다. 파일 저장 시 workspace 쓰기가 추가로 필요하다.
- **Run Condition:** 범위와 자료가 주어진 때 정적 비교한다. Scheduled는 검증·사람 승인 뒤 고려할 후보이며 자동 실행 권한과 시점은 미확인이다.
- **Stop Condition:** 자료 부재, 정책 충돌·보류, 정적 분석으로 판정할 수 없는 동작 또는 추가 권한 필요 시 해당 항목을 미확인으로 보고한다.
- **Human Approval Needed:** 정책 해석, 후보 채택·수정 범위, Scheduled 사용 여부를 사람이 결정한다.
- **Failure Alert:** 대상·기준 버전, 완료 단계, 확인 범위, 미실행 사항·누락·필요 권한 및 사람 결정을 보고한다. 외부 알림 수단은 미확인이다.
