# Scheduled 연결 전 중단 조건

이 문서는 [`pr-preflight`](../../.agents/skills/pr-preflight/SKILL.md)를 Scheduled에 연결하기 전의 준비 계약이다. 사람은 기존의 일관된 보류·사람 이관 관찰을 근거로 **읽기 전용 범위의 Scheduled 생성**을 승인했다. 이 승인은 동일 입력 행동 비교 완료, Skill 행동의 완전한 검증, Scheduled 권한 확인 또는 Scheduled의 즉시 생성·실행을 뜻하지 않는다.

## 준비와 행동 판정의 구분

| 구분 | 이 문서가 하는 일 | 이 문서만으로 주장할 수 없는 일 |
| --- | --- | --- |
| 작업 준비 | 입력·중단·사람 재개 증거를 정한다. | Skill이 실제로 중단 조건을 수행했다는 판정 |
| 행동 비교 | 동일 입력의 독립 일반 요청과 새 세션 Skill 요청을 대조할 기준을 정한다. | 서로 다른 입력·기준선의 기존 실행이 동등하다는 판정 |
| Scheduled 권한 | 필요한 권한을 작업별로 확인하도록 요구한다. | 일반 세션·권한 상승 세션 성공이 Scheduled에서도 가능하다는 판정 |

## 중단 조건과 재개 증거

| 중단 유형 | 감지 신호 | 보존할 상태 | Failure Alert 항목 | 재개 주체 | retry 상한 |
| --- | --- | --- | --- | --- | --- |
| 같은 오류 3회 반복 | 같은 입력과 원인에서 동일 오류가 세 번째 확인됨 | 입력, 오류 원문, 반복 횟수, 마지막 완료 단계 | 반복된 명령·오류와 사람이 결정할 다음 조치 | 사람 | 두 번까지만 재시도하고 세 번째에 중단 |
| 변경 파일 수·경로 초과 | 승인한 파일 수 또는 경로와 실제 diff가 다름 | 기준선, 승인 범위, 변경 파일 목록 | 범위 밖 파일과 포함·제외 결정 요청 | 사람 | 재시도하지 않음 |
| 외부 권한 필요 | 네트워크·GitHub·앱·workspace 밖 접근이 필요함 | 마지막 완료 단계와 미실행 작업 | 필요한 권한의 목적·대상·읽기/쓰기 범위 | 사람 | 권한 승인 전 재시도하지 않음 |
| 불명확한 테스트 실패 | 환경·테스트·구현 중 원인을 근거로 구분할 수 없음 | 명령, 종료 상태, 첫 관련 오류, 수집된 테스트 수 | 원인 미확정과 추가 조사에 필요한 입력 | 사람 | 자동 재시도하지 않음 |
| 민감 화면 필요 | 비밀·고객정보가 있는 화면이나 원문 접근이 필요함 | 민감값을 제외한 위치·유형과 완료 단계 | 마스킹·대체 입력·접근 승인 요청 | 사람 | 자동 재시도하지 않음 |
| 입력·정책·승인 근거 누락 | 대상, 기준선, PR diff, 승인 범위 또는 정책이 없거나 충돌함 | 확인한 입력과 누락·충돌 지점 | 보류한 checklist 항목과 재개에 필요한 결정 | 사람 | 입력이 보완되기 전 재시도하지 않음 |
| 행동 비교 조건 불일치 | 일반 요청과 Skill 요청의 대상·기준선·권한이 다름 | 두 실행의 입력과 다섯 비교 축 결과 | 비교할 수 없는 축과 필요한 동일 입력 | 사람 | 같은 입력을 승인하기 전 재시도하지 않음 |

## Scheduled 생성 전 승인 게이트

아래 게이트는 실행 범위를 넓히지 않는 조건이다. 동일 입력 행동 비교가 미완료인 점은 사람의 제한적 승인으로 읽기 전용 생성의 차단 사유가 아니지만, 쓰기·외부 접근·추가 권한이 필요한 Scheduled에는 계속 차단 사유다.

1. 동일한 대상·기준선·diff·승인 계획·정책·검증 근거를 사용한 새 세션 일반 요청과 새 세션 Skill 요청을 독립 실행하고, 절차 재사용·출력 구조·가변 입력 처리·중단 행동·사람 입력을 비교한다.
2. 입력/범위 불명확 또는 권한 불가 상황에서 Skill이 추정·자동 재시도·외부 쓰기 없이 중단하고 마지막 완료 단계·미실행·필요 결정을 남기는지 검토한다.
3. Scheduled 환경의 로컬 읽기, 허용된 보고 저장, Git read, 검증 명령, 필요 시 로컬 HTTP 바인딩, 네트워크/GitHub, 알림 권한을 각각 확인한다. 일반 세션 결과는 이 증거를 대체하지 않는다.
4. 사람은 입력 출처·최신성·대상, 허용 명령과 권한, 보고 위치·보존, 알림 여부·수신자, 실행 주기와 실패 후 처리 범위를 승인한다.
5. 위 증거와 보류 항목을 검토한 뒤 사람이 Scheduled 생성 자체를 명시적으로 승인한다.

## 승인된 읽기 전용 경계

- 허용 범위는 로컬 읽기와 Git read에 기반한 검토 및 세션 내 보고다. 앱·테스트·패키지·Git 상태를 수정하거나 stage·commit·게시·외부 쓰기를 하지 않는다.
- Scheduled 실행에 로컬 HTTP 바인딩, 네트워크/GitHub, 외부 알림, workspace 보고 파일 저장 또는 그 밖의 추가 권한이 필요하면 실행하지 않는다. 필요한 권한·목적·대상·마지막 완료 단계·미실행 항목을 남기고 종료한다.
- 실제 생성 요청 때 이름·실행 시점/주기·보고 위치 또는 알림 방식이 제공되지 않으면 이를 추정하지 않고 사람에게 요청한다.
- 동일 입력 행동 비교와 독립 중단 행동 시험은 계속 미완료다. 읽기 전용 승인 밖의 범위 확대 또는 안전성 일반화의 근거로 사용하지 않는다.

## 현재 상태

**읽기 전용 생성은 사람 승인, 실행 권한은 미확인.** Lab 19의 일반 요청과 Skill 요청은 입력·기준선이 달라 동일 입력의 독립 비교가 아니다. Scheduled sandbox, 로컬 HTTP 바인딩, GitHub 네트워크/인증, 외부 알림 전달 권한도 미확인이다. 이 문서는 필요한 증거를 정의할 뿐 이를 대체하지 않는다.
