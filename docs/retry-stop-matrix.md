# 결제 재시도·중단 참조 매트릭스

이 문서는 다음 변경에서 결제 실패·예외 처리의 경계를 빠르게 확인하기 위한 참조입니다. 결제 결과, 상태 전환, 재고 처리는 [결제 정책](payment-policy.md)과 연결된 주문·재고 정책이 정본이며, 이 문서는 이를 대체하지 않습니다.

## 확정된 판단

| 사건 | 감지 신호 | 재시도·중단 판단 | 중단 뒤 행동 | 근거 |
| --- | --- | --- | --- | --- |
| 판정된 결제 실패 | HTTP `402`, 실패 결제 정보·이력, 주문 상태 `payment_failed` | 동일 주문의 새 결제는 하지 않음 | 실패 주문·이력을 보존하고 상태·재고를 임의로 바꾸지 않음 | 결제 정책의 실패 처리·동일 주문 재결제 금지 |
| `payment_failed` 주문의 재결제 요청 | 실패 주문 ID에 대한 새 결제 요청 | 거부함 | 기존 주문 상태·결제 이력·재고를 변경하지 않음 | 결제 정책의 동일 주문 재결제 정책 |
| 예기치 못한 서버 예외 | HTTP `500`, `{ ok: false, error: "internal_error", requestId }` | 결제 성공·실패로 판정하지 않음 | 외부에는 내부 세부 정보를 노출하지 않고 `requestId`로 서버 보존 정보와 연결함 | 이 문서의 세션 승인 경계 |

## 사람 확인이 더 필요한 판단

| 사건 | 현재 감지 신호 | 재시도·중단 판단 | 다음 행동 | 정책 상태 |
| --- | --- | --- | --- | --- |
| 네트워크·인프라 실패 | 연결 실패, 시간 초과, 전송 중단 등 결제 결과를 확정할 수 없는 신호 | **사람 승인 전 후보** | 성공·실패·재결제 가능 여부를 추정하지 말고 근거를 보존한 뒤 사람 결정을 요청 | 결제 정책에서 허용 조건·식별 방식·횟수 보류 |
| 예기치 못한 예외를 주문·이력에 반영 | `500` 내부 오류 응답과 서버 오류 보존 | **사람 승인 전 후보** | 예외만으로 `payment_failed` 전환이나 실패 이력 생성을 하지 않음 | 세션 승인 범위 밖; 별도 결정 필요 |
| 결제 시점 재고 부족 | 결제 완료 직전 재고 부족 검사 | **사람 승인 전 후보** | 결제 성공으로 확정하지 않으며, 상태·결제 이력·응답 계약을 현재 구현값만으로 확정하지 않음 | 결제 정책에서 HTTP 상태·오류 코드·본문 보류; 상태·재고는 연결 정책 확인 필요 |
| 환불·부분 환불 | 금액 반환 또는 재고 복원 요구 | **사람 승인 전 후보** | 결제·주문 상태·재고 정책을 함께 검토하고 사람 결정을 요청 | 환불 API·금액 반환·부분 환불 보류 |

## 세션 승인: 예기치 못한 예외 처리 경계

이번 세션에서 사람은 예기치 못한 예외에 대해 다음만 승인했습니다.

- 외부 응답: HTTP `500`, `{ ok: false, error: "internal_error", requestId }`
- 서버 보존: `console.error`에 오류 종류, `requestId`, 주문 ID, 처리 단계, 메시지·스택, 전후 상태, 발생 위치를 기록
- 외부 본문에는 내부 오류 메시지·스택·카드 정보를 포함하지 않음
- 이 예외 경계는 판정된 결제 실패의 HTTP `402`·`payment_failed` 전환과 별개이며, 상태·이력·재고의 새 규칙을 정하지 않음

- [ ] 동일 `payment_failed` 주문에 대한 새 결제를 허용하거나 성공 처리하지 않는가?
- [ ] 예외 응답이 승인된 `500` 본문만 제공하고 내부 메시지·스택·카드 정보를 노출하지 않는가?
- [ ] 예외 로그에 승인된 추적 정보가 남고, `requestId`로 외부 응답과 연결되는가?
- [ ] 재시도 조건·식별 방식·횟수, 결제 시점 재고 부족의 응답, 환불·부분 환불 중 새 결정을 요구하는 항목을 사람에게 확인했는가?
- [ ] 변경 전후 주문 상태·결제 이력·재고의 의미가 정본 정책과 일치하는가?
