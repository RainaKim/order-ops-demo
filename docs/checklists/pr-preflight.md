# PR 사전 점검 체크리스트

PR을 열기 전에 변경 범위·정책·검증 근거를 대조합니다. 이 문서는 실행 결과를 기록하는 양식이 아니라, 다음 변경에서 반복 사용하는 확인 항목입니다.

| 항목 | 방법 또는 관찰 대상 | 자동 또는 사람 판단 | 실패·보류 시 행동 |
| --- | --- | --- | --- |
| Scope | 기준선, 현재 diff, 승인 계획의 Files to Change·Out of Scope를 대조하고 각 변경 파일을 정책·승인 계획·코드·테스트·검증 기록 중 하나로 분류한다. 어느 분류에도 맞지 않는 파일은 범위 밖 후보로 표시한다. | diff 목록은 자동 확인 가능, 범위 적합성은 사람 판단 | 범위 밖 후보를 PR에서 분리하거나 승인 계획을 갱신한다. 근거가 없으면 구현·커밋을 멈춘다. |
| Policy | 변경된 동작을 관련 정책의 확정 판단·보류 사항·다른 정책의 책임 경계와 대조한다. 보조 참조 문서는 정본 정책을 대체하지 않는다. | 사람 판단 | 정책이 없거나 충돌·보류되면 임의로 상태·응답·저장 규칙을 정하지 말고 사람 결정을 요청한다. |
| Tests | 새 동작과 회귀 위험에 대해 응답, 저장 상태, 재고 등 관찰 가능한 결과를 assertion으로 확인한다. 기대 실패는 승인된 정책 불일치만 사용한다. | 테스트 실행은 자동, 케이스의 충분성·기대 실패 승인은 사람 판단 | 빠진 assertion을 추가하거나, 구현 불일치라면 정책·승인 근거를 확인한다. 테스트 자체 문제와 정책 미결 항목을 기대 실패로 숨기지 않는다. |
| Lint | 저장소가 지정한 lint 명령과 대상 경로가 현재 변경을 포함하는지 확인한다. | 자동 | lint 오류를 해결한다. 규칙 예외나 설정 변경이 필요하면 별도 근거와 승인을 확인한다. |
| Typecheck | 저장소가 지정한 typecheck 명령으로 변경된 코드·테스트의 타입 경계를 확인한다. | 자동 | 타입 오류의 실제 위치와 원인을 보존하고 수정한다. 존재하지 않는 API·옵션·비동기 가정을 fallback으로 감추지 않는다. |
| Diff | staged 또는 PR diff를 승인 계획·정책·테스트와 다시 대조한다. 의도하지 않은 파일, 민감 정보, 불필요한 포맷 변경, 기존 변경 덮어쓰기를 확인한다. | diff 목록·정적 검사는 자동 가능, 적합성은 사람 판단 | 예상 밖 변경을 분리·되돌리거나 승인 범위를 갱신한다. 다른 작업자의 변경은 승인 없이 제거하지 않는다. |
| Failure handling | 오류 경로가 빈 값·성공처럼 보이는 응답·로그만으로 원인을 숨기지 않는지 확인한다. 외부 응답, 서버 보존, 상태·이력·재고의 처리 경계를 정책과 승인 기록에 대조한다. | 일부 경로 실행은 자동, 오류 분류·외부 계약은 사람 판단 | 예외를 판정된 도메인 실패로 추정하지 않는다. 승인되지 않은 상태 코드·본문·저장 방식·재시도 규칙은 사람 결정 전까지 보류한다. |
